# Technology Stack

**Analysis Date:** 2026-09-25

## Languages

**Primary:**
- Python 3.10+ - MCP server, composition algorithms, audio analysis, library indexing, and CLI scripts under `mcp_server/ableton_claude/` and `scripts/`; the requirement is declared in `mcp_server/pyproject.toml`.
- Python in Ableton Live's embedded runtime - the Remote Script in `remote_script/ClaudeBridge/__init__.py` and `remote_script/ClaudeBridge/handlers.py` imports Ableton-only `_Framework` and `Live` modules and runs inside Live rather than the MCP virtual environment.

**Secondary:**
- Bash - Remote Script installation in `scripts/install_remote_script.sh`.
- JSON - newline-delimited bridge messages in `mcp_server/ableton_claude/client.py` and `remote_script/ClaudeBridge/__init__.py`; genre profiles and analysis caches under `knowledge/`.
- Ableton groove XML (`.agr`) - generated by editing a stock groove template in `mcp_server/ableton_claude/ear/groove_file.py`.

## Runtime

**Environment:**
- CPython >=3.10 for the MCP process, declared in `mcp_server/pyproject.toml`; the checked-in lock resolves Python 3.10 through 3.14 with platform markers in `mcp_server/uv.lock`.
- Ableton Live's embedded Python runtime for `remote_script/ClaudeBridge/`; it supplies the proprietary `Live` and `_Framework` APIs.
- Ableton Live version is not pinned. Code comments in `remote_script/ClaudeBridge/handlers.py` document behavior measured on Live 12.4, while the groove integration is labeled Live 11+.

**Package Manager:**
- uv - setup and execution use `uv run` in `README.md`; local inspection used uv 0.12.19.
- Lockfile: present at `mcp_server/uv.lock`, with a marker-aware lock for macOS/Linux/Windows and multiple Python versions.
- Build backend: Hatchling, configured in `mcp_server/pyproject.toml`.

## Frameworks

**Core:**
- MCP Python SDK `mcp>=1.2,<2` (locked to 1.30.0) - exposes 33 typed tools through `FastMCP` in `mcp_server/ableton_claude/server.py`.
- Ableton Control Surface framework - `remote_script/ClaudeBridge/__init__.py` subclasses `_Framework.ControlSurface.ControlSurface` and transfers bridge requests to Live's main thread.
- Ableton Live Object Model - 50 registered commands in `remote_script/ClaudeBridge/handlers.py` read and mutate songs, tracks, arrangement clips, MIDI, devices, parameters, routing, locators, transport, Groove Pool state, and real-time resampling.

**Testing:**
- pytest `>=8` (locked to 9.1.1) - offline unit and bridge-plumbing tests under `mcp_server/tests/`.
- Live smoke runner - `scripts/smoke_live.py` exercises the actual TCP bridge and running Ableton instance.

**Build/Dev:**
- Hatchling - builds the `ableton_claude` Python package and console entry point declared in `mcp_server/pyproject.toml`.
- uv - creates the environment, installs default `dev` and `ear` dependency groups, and launches the stdio MCP command.
- FFmpeg - undeclared system executable used as a fallback decoder by `mcp_server/ableton_claude/references.py` and for MP3 encode/decode in `mcp_server/ableton_claude/export.py`.

## Key Dependencies

**Critical:**
- `mcp` `>=1.2,<2` - standard Model Context Protocol server and FastMCP tool registration in `mcp_server/ableton_claude/server.py`.
- `numpy` `>=1.26` - signal arrays, FFTs, music/audio feature extraction, and numeric generation throughout `mcp_server/ableton_claude/`; lock versions vary by Python (2.2.6, 2.4.6, or 2.5.3).
- `scipy` `>=1.11` - filters, resampling, peak/spectral operations in `mcp_server/ableton_claude/analysis.py`, `mcp_server/ableton_claude/references.py`, `mcp_server/ableton_claude/timbre.py`, `mcp_server/ableton_claude/loops.py`, and `mcp_server/ableton_claude/ear/`; lock versions vary by Python (1.15.3, 1.17.1, or 1.18.1).
- `soundfile` `>=0.12` (locked to 0.14.0) - libsndfile-based audio I/O in `mcp_server/ableton_claude/analysis.py`, `mcp_server/ableton_claude/references.py`, `mcp_server/ableton_claude/library.py`, and loop/export modules.
- `pyloudnorm` `>=0.1.1` (locked to 0.2.0) - integrated loudness measurement in `mcp_server/ableton_claude/analysis.py`, `mcp_server/ableton_claude/references.py`, `mcp_server/ableton_claude/export.py`, and `mcp_server/ableton_claude/ear/arrangement.py`.

**Infrastructure:**
- Beat This 1.1.0 - neural beat/downbeat detection in `mcp_server/ableton_claude/ear/grid.py`; sourced from the moving GitHub `main.zip` URL declared in `mcp_server/pyproject.toml` and hash-locked in `mcp_server/uv.lock`.
- Demucs `>=4.0.1` - `htdemucs` source separation into drums, bass, other, and vocals in `mcp_server/ableton_claude/ear/stems.py`; the lock selects 4.0.1 for Intel macOS and 4.1.0 elsewhere.
- PyTorch `>=2.14.0` and torchaudio `>=2.11.0` - inference runtime for Beat This and Demucs; `mcp_server/ableton_claude/ear/grid.py` and `mcp_server/ableton_claude/ear/stems.py` prefer Apple MPS and fall back to CPU.
- Python standard-library TCP sockets - local bridge transport in `mcp_server/ableton_claude/client.py` and `remote_script/ClaudeBridge/__init__.py`.

## Music-Generation Capability

**Generation present:**
- Deterministic MIDI/harmony generation is implemented, not merely planned: chord parsing and voice leading in `mcp_server/ableton_claude/music/theory.py`, progression construction in `mcp_server/ableton_claude/music/harmony.py`, call-and-response melody in `mcp_server/ableton_claude/music/melody.py`, and drum/build patterns in `mcp_server/ableton_claude/music/groove.py`.
- Song-scale construction is exposed as MCP tools in `mcp_server/ableton_claude/server.py`, then materialized in Live with `create_midi_clip`, `create_audio_clip`, `load_device`, `set_param`, routing, groove, automation, and arrangement commands implemented in `remote_script/ClaudeBridge/handlers.py`.
- Reference-guided generation is supported through analysis/profile code in `mcp_server/ableton_claude/references.py`, `mcp_server/ableton_claude/knowledge.py`, `mcp_server/ableton_claude/tension.py`, `mcp_server/ableton_claude/timbre.py`, and `mcp_server/ableton_claude/ear/`.
- Real audio output is produced by Live, not synthesized by this Python package. `record_master` in `remote_script/ClaudeBridge/handlers.py` records the master to an armed Resampling track in real time and returns Live's rendered file path.

**Generation boundaries:**
- No text-to-audio or pretrained music-generation model is included. The neural models are analysis-only: Beat This detects timing and Demucs separates stems.
- The MCP client/model supplies creative intent and sequences tool calls; the server supplies deterministic composition helpers, measurements, and DAW control.
- Ableton devices, presets, plug-ins, sample packs, and an available audio output device determine the final sound. The repository does not bundle those assets.

## Model and Vendor Coupling

**Model coupling:**
- No Anthropic, OpenAI, Google, or other LLM SDK/API is imported anywhere in `mcp_server/`, `remote_script/`, or `scripts/`; no model API key is required.
- The executable calls `mcp.run()` in `mcp_server/ableton_claude/server.py`, which makes the installed console command a standard stdio MCP server. Any MCP-capable host can launch it and discover the same typed tools.
- Claude-specific coupling is naming and prompt text: package/server names in `mcp_server/pyproject.toml` and `mcp_server/ableton_claude/server.py`, Remote Script name `ClaudeBridge`, the install path in `scripts/install_remote_script.sh`, and instructional wording/default track names. None of these are part of an LLM API dependency.
- To present the project as vendor-neutral, rename branding and rewrite MCP instructions, but keep the MCP schemas and local bridge protocol. No core control or generation rewrite is required.

**Ableton coupling:**
- DAW mutation is tightly coupled to Ableton's proprietary Live Object Model in `remote_script/ClaudeBridge/handlers.py` and cannot be reused with another DAW without a new adapter.
- The MCP/composition/audio-analysis layer is separable from the Ableton adapter: direct Ableton calls are concentrated in `mcp_server/ableton_claude/client.py` and `remote_script/ClaudeBridge/`.

## Configuration

**Environment:**
- No `.env` files were detected and no secret/API-key environment variables are consumed by the Python code.
- `ABLETON_USER_LIBRARY` is the only explicit environment override; `scripts/install_remote_script.sh` otherwise installs under `$HOME/Music/Ableton/User Library/Remote Scripts/ClaudeBridge`.
- Bridge host and port are hard-coded to `127.0.0.1:9878` in `mcp_server/ableton_claude/client.py` and `remote_script/ClaudeBridge/__init__.py`.
- Genre/profile, ear-cache, and sample-index locations are derived from the repository in `mcp_server/ableton_claude/knowledge.py`, `mcp_server/ableton_claude/ear/listen.py`, and `mcp_server/ableton_claude/library.py`.

**Build:**
- `mcp_server/pyproject.toml` defines metadata, dependency groups, the `ableton-claude-mcp` console script, Hatchling backend, and package inclusion.
- `mcp_server/uv.lock` pins the resolved dependency graph.
- No Dockerfile, CI workflow, `.python-version`, or cross-platform installer is present.

## Platform Requirements

**Development:**
- Python >=3.10 and uv for the MCP/analysis process; install from `mcp_server/pyproject.toml` and `mcp_server/uv.lock`.
- Ableton Live with the copied `remote_script/ClaudeBridge/` selected in a Control Surface slot for control and rendering.
- FFmpeg on `PATH` for M4A/other libsndfile fallback decoding and MP3 export.
- Significant CPU/RAM or Apple MPS for the optional `ear` workflow. `mcp_server/ableton_claude/ear/stems.py` notes that a six-minute stereo stem is roughly 127 MB in float form, and separation keeps four stems in memory.
- First use of Beat This or Demucs can require network access to obtain pretrained model weights; subsequent use relies on framework caches.

**Production:**
- Deployment target is a local desktop running Ableton Live, not a stateless web service. MCP stdio and the bridge's loopback TCP socket assume the MCP process and Live run on the same machine.
- `scripts/install_remote_script.sh` is macOS-oriented by default, and `mcp_server/ableton_claude/ear/groove_file.py` hard-codes `/Applications/Ableton Live 12 Suite.app/...` plus a macOS-style user-library path. Core MCP/audio code is otherwise Python-portable, but Windows support needs path/configuration work.
- Live has no save/export API in this integration: users save sets in Live, while rendering is real-time Resampling, as documented in `README.md` and implemented in `remote_script/ClaudeBridge/handlers.py`.
